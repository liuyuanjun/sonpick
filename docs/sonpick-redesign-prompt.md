# Sonpick 拾音 · 全系统重设计提示词包

> 用途：把本文件交给**另一个设计工具 / AI**（Figma Make、v0、Stitch、Lovable、Claude/ChatGPT、Midjourney 等）来**重新设计整套系统**。
> 用法：先做两个决策 → 复制「主提示词」→ 按需追加「模块化提示词」→ 附上素材。

---

## 0. 使用前：先做 2 个决策

**决策一 · 品牌延续度**（决定 LOGO/吉祥物/主色是否重做）

| 档位 | 含义 | 适用 |
|------|------|------|
| **A · 精修（Refine）** | 保留 LOGO 造型、吉祥物「拾耳」、emerald 主色；只做质感/一致性升级 | 想快速提升，不承担品牌重构风险 |
| **B · 焕新（Refresh）** | 保留母题（声波/音符/大耳狐），但主色系可换、LOGO 可重新绘制、吉祥物可重绘 | 想要明显改观 |
| **C · 重构（Reimagine）** | 从零建立全新视觉语言，仅保留「乐海拾音」的母题与产品定位 | 想要彻底换血 |

> 默认推荐 **B**。文档中以 `【模式】` 标注各档差异。

**决策二 · 目标工具类型**（决定提示词形态）
- **设计/代码类 LLM**（v0、Stitch、Lovable、Figma Make、Claude、ChatGPT）→ 用第 1–3 部分（文字 brief）。
- **纯图像生成**（Midjourney、SD、即梦等）→ 用第 4 部分（短提示）。

**必须随提示词附上的素材**
1. 现有 LOGO：`web/public/brand/logo.png`
2. 吉祥物：`web/public/brand/mascot/mascot-main.png`（+ expressions / scenes）
3. 现有界面截图：概览页、曲库页、播放器大抽屉（舞台三皮肤）、登录页、移动端
4. 本文件（可作为设计约束附件）

## 1. 主提示词（Master Brief · 直接复制）

```
你是一位资深产品设计师，请为一个「自托管的个人音乐库」Web 应用重新设计整套视觉与交互系统。

【产品介绍】
- 名称：Sonpick 拾音；Slogan「乐海拾音，好歌不散」。
- 定位：可部署在 NAS 上的个人音乐下载与曲库管理 Web 应用。单用户、自托管、私有云。
- 用户：懂技术的自托管爱好者（NAS + Docker），拥有本地/WebDAV 音乐库，重视隐私、掌控感与音质。
- 非目标：多用户、公网商业化、任何版权绕过。请勿设计成社交/流媒体信息流形态。

【核心场景与页面】
1. 搜索并批量下载歌曲（QQ 音乐源）。
2. 浏览曲库：播放、转码 MP3、删除、整理、刮削元信息、获取歌词。
3. WebDAV 远程库：连接配置、目录浏览、代理播放、上传（音频+封面+歌词）。
4. 操作日志与任务中心（下载/上传/删除/转码进度）。
页面清单：概览(Dashboard)、登录、曲库、下载(搜索/导入)、播放器、设置、日志、曲库源、WebDAV。

【信息架构（必须保留的结构）】
- 桌面：左侧栏（展开 220px / 折叠 64px）+ 内容区 + 底部常驻悬浮播放胶囊 + 「大播放器抽屉」。
- 移动：极简顶栏 + 底部 Tab 栏（概览/播放器/下载/曲库/设置，52px + 安全区）+ 播放胶囊。
- 播放器是核心特色，三层外壳：① 列表页；② 底部胶囊（唯一音频出口）；③ 大播放器抽屉（唯一宿主，含舞台三皮肤：黑胶 / 叠层封面 / 纯歌词）。

【设计目标（情感）】
沉静、专注、有温度、掌控感。像在自家唱片室翻阅唱片，而不是刷流媒体信息流。信息密度优先但分区清晰；专业级播放器体验。

【需要你输出的设计系统】
1. 视觉主题与氛围（设计哲学 + 3–5 个核心特征关键词）。
2. 配色系统：主色/辅色/中性底与面/描边/语义色（成功·警告·错误·信息）/分类强调色（≥6 个，用于 KPI 与活动流）；明暗两套并列；所有前景文字对背景须满足 WCAG AA 4.5:1（大字/图标 ≥3:1）。
3. 字体系统：西文 + 中文配对、完整字号层级表（字号/字重/行高/字距）、数字必须等宽对齐（时长、体积、进度）。
4. 形状语言：圆角尺度、图标语言、按钮/卡片/输入框几何。
5. 光影与质感：阴影层级、表面层级、玻璃/纹理使用边界。
6. 组件规范：按钮（主/次/幽灵/危险）、卡片、输入框、导航、标签/徽章、KPI 卡、弹窗/抽屉、空/加载/错误态。
7. 布局：间距基数与倍数、栅格、容器宽度、区块间距、响应式断点（≤768 / 769–1024 / 1025–1280 / >1280）与触控目标最小尺寸。
8. 动效：时长/缓动/可动属性，必须支持 prefers-reduced-motion。
9. LOGO 与吉祥物的使用规范（若为焕新/重构档，请给出新方案）。

【约束】
- 中文优先（界面文案为简体中文），西文用于品牌名与数字。
- 暗色为默认主题，明亮模式为完整对等的第二主题（非附属）。
- 禁止大面积铺设渐变/高饱和色块；强调色只作点缀。
- 不做多用户、社交、版权绕过相关形态。

【交付要求】
先给设计系统规范（Token 表：颜色/字号/间距/圆角/阴影，均带精确数值），再给 5 个关键页面的高保真设计（概览、曲库、播放器大抽屉、登录、移动端），明暗双模，注明每处的设计意图。
```

## 2. 模块化提示词（按需追加到主提示词之后）

### 2.1 配色建议（三选一或让工具给方案）

**方向 A「深海翡翠 · 延续」（推荐作为基线）**
- 主色 emerald 青绿（现有 `#10B981`；亮色文字场景降至 `#047857`）。
- 辅色 靛蓝（现有 `#6366F1`），仅信息/次要强调。
- 底/面/描边 近黑 `#0B0C10` / `#14161C` / `#23262F`；文字 `#ECEEF2`/`#B6BECB`/`#8B95A5`。
- 分类强调色 7 个：青绿 teal / 蓝 blue / 玫红 rose / 琥珀 amber / 天蓝 sky / 绿 green / 石板 slate（明暗两套）。
- 特点：冷静、克制、护眼；改动最小。

**方向 B「午夜蓝紫 · 夜间电台」**
- 主色改 靛蓝/紫（如 `#6366F1` 或 `#7C6BF5`），青绿降为点缀。
- 底更深更冷（如 `#0A0B12` / `#12141C`）；强调用高亮蓝紫。
- 特点：更"科技/深夜电台"，与市面音乐流媒体气质接近，差异化略弱。

**方向 C「暖黑胶 · 发烧器材」**
- 底 近黑暖调（如 `#0D0B0A` / `#17130F`）；主色改 琥珀/铜金（如 `#C8863C`）或暖橙，冷色降为辅助。
- 质感偏「音响器材面板 / 黑胶封套」，可引入细腻颗粒与铜金描边。
- 特点：最"发烧级"、最有温度；但与现有品牌色跨度最大。

> 要求工具对选中方向同时给出：主/辅/中性/语义/分类色的 **HEX + 明暗两套 + 对比度校验**。

### 2.2 字体建议（三选一）

**方向 A「无衬线理性 · 延续」**
- 西文 `Inter`；中文 `Noto Sans SC`（备选 `HarmonyOS Sans` / `MiSans`）。
- 特点：中性、清晰、工程感强。

**方向 B「几何现代」**
- 西文 `Space Grotesk` 或 `Inter Display`；中文 `思源黑体`。
- 数字用 `tabular-nums` / `@fontsource` 等宽；标题可加负字距。
- 特点：更有设计感与现代度。

**方向 C「唱片质感」**
- 标题用衬线：`Fraunces` / `Playfair Display` / `Noto Serif SC`（营造"专辑封面/厂牌"感）；正文仍无衬线。
- 特点：最贴合"唱片室"母题，但需控制衬线使用面积，避免花哨。

> 通用要求：给出完整层级表（Display/H1/H2/H3/Body/Small/Caption，含字号·字重·行高·字距）；字重仅用 400/500/600/700/800；中文正文行高 ≥1.6；**字体必须真实加载方案**（自托管 woff2 或 fontsource）。

### 2.3 形状语言与圆角

- 现状：8/10/12/14/16/20/24px 混用（需归一）。
- **圆润方案**：卡片 16 / 按钮 10 / 大容器 20–24 / 胶囊 999 —— 亲和、现代。
- **硬朗方案**：卡片 8 / 按钮 6 / 大容器 12，接近「唱片封套直角」——更冷、更器材感。
- 要求：为每个组件指定统一圆角，避免混用。

### 2.4 光影与质感

- 基线：微阴影 + `color-mix` 软底塑层；卡片阴影如 `0 10px 24px rgba(21,32,53,.05)`；暗色浮层阴影偏黑（更实），亮色偏冷蓝灰（更柔）。
- 玻璃质感：移动 Tab 与浮层用 `backdrop-filter: blur(14px)` + 半透明底。
- 黑胶纹理：播放器黑胶皮肤可引入沟槽纹理与高光；**投影不要挂在自转层上**（会跟着转）。
- 禁忌：禁止大面积渐变/发光；品牌渐变只用于 LOGO/焦点/强调条。

### 2.5 LOGO

- **模式 A（精修）**：保留现有造型——圆角方形深底上，**两圈同向同心声波弧线**（左下开口、圆头端）+ 居中**八分音符**（椭圆符头+符干+S 形符旗）；渐变 亮绿→青→蓝→紫。仅优化材质与清晰度。注意：源为位图，**禁止矢量化描摹**，需要新尺寸从源图导出。
- **模式 B/C（焕新/重构）**：可重新设计，但须延续母题「乐海 · 声波 · 拾音」；输出：主标 + 单色版 + 小尺寸（≤32px）版 + 深色底/浅色底两套用法；给出安全区与最小尺寸。

### 2.6 吉祥物

- 现有形象「拾耳」：戴耳机的**大耳狐**；暖橙 `#F5A45D` 主色、奶白 `#F7F1E8`、深墨 `#2B2118`；耳机用品牌色（青绿头梁 + 蓝紫耳罩）；头身比约 1:1.2，耳高≈头高 0.9。
- 要求（A/B 档保留形象，C 档可重绘）：
  - **4 个表情**：听歌 / 开心 / 惊讶 / 找不到歌。
  - **3 个场景**：空曲库 / 加载中 / 出错。
  - 统一 2:1 横构图，四周留 8% 呼吸区。
  - 使用场景：空状态、加载动画、错误页、引导页。
  - **设计边界**：暖橙属吉祥物专属，禁止挪作状态语义色（避免与"警告"混淆）。

### 2.7 图标

- 现状问题：曾有一套自研图标（24×24、2px 线宽、round 端点、`stroke=currentColor`）但未被采用，实际使用 Ionicons。
- 要求：**指定唯一图标语言**（线性或面性，统一线宽与圆角），24×24 网格，`currentColor` 着色；给出核心图标清单（搜索/下载/曲库/播放/WebDAV/转码/日志/设置/任务/上传/删除/歌词/刮削/收藏/随机/扫描/刷新/音质/用户/主题）。

### 2.8 动效

- 时长：微交互 120ms / 常规 200–240ms / 浮层进出 240–280ms。
- 缓动：进入 `cubic-bezier(.22,1,.36,1)`；退出 ease-in。
- 只动 `transform` / `opacity`。
- 必须支持 `prefers-reduced-motion`（唱片自转、扫光、进度脉冲等持续动效需可关闭）。

### 2.9 布局与信息架构

- 间距基数 4px，倍数 4/8/12/16/20/24/32/40/48。
- 内容最大宽度 1280px 居中；概览用主从栅格（左主 1.35fr / 右侧栏 0.9fr）。
- 底部播放胶囊几何（桌面高 84px、间距 24px；移动高 60px）为其预留底部空间。
- 断点：≤768 移动（底部 Tab）；769–1024 侧栏折叠 64px；1025–1280 完整侧栏 220px；>1280 居中限宽。
- 触控目标 ≥36×36px（圆形图标按钮 ≥40px）。

### 2.10 组件库

覆盖并给出精确 CSS 参数：主/次/幽灵/危险按钮、卡片/面板、输入框（含 focus 光环）、侧栏菜单（默认/激活/hover）、标签与徽章、KPI 卡（图标软底 + 数值）、列表行、弹窗/抽屉（遮罩、内容区、进场）、**空/加载/错误三态**。

### 2.11 明暗主题与可访问性

- 暗色为默认；明亮模式完整对等。
- 所有文字对比度 ≥ WCAG AA 4.5:1；主色在亮色下若对比不足需降阶（如 emerald `#10B981` → `#047857`）。
- 暖色/语义色需在双模下分别校验。
- 键盘可达：可见 focus 环、合理的 focus 顺序、`aria-label`。

## 3. 红线与约束（必须写进任何提示词）

1. **产品边界不扩**：不做多用户、不做社交/信息流、不做版权绕过。
2. **中文优先**，文案为简体中文。
3. **播放器三层结构**（列表 / 底部胶囊 / 大播放器抽屉）与底部常驻播放器是产品核心，不得简化掉。
4. **暗色为默认**，明亮模式必须同等完整。
5. 若 **模式 A**：不得改变 LOGO 造型与吉祥物形象；不得对 LOGO 位图做矢量化描摹。
6. **禁止大面积铺品牌渐变**；渐变仅用于 LOGO / 焦点态 / 强调条。
7. 自托管属性要在气质上体现（克制、无广告、无社交杂音）。
